# FAQ

Here are answers to questions about learning with dewstack.
[Troubleshooting](tutorial:troubleshooting) offers help when something
does not work.

## Do I need to know how to code before I start?

No. The first tutorials introduce the tools and show examples you can
try. Later pages build on those ideas. You can return to an earlier
explanation whenever it helps.

## Do I need an account or anything to install?

You can read the tutorials and try the data exercises in your browser
without an account or anything to install.

The website exercises use a free GitHub account. GitHub keeps your
website files and publishes your site. Its website includes an editor,
so you can work in your browser. If you prefer an editor on your
computer, VS Code is one option.

## Is this graded?

The tutorials and exercises are not graded. The college grades the two
projects and the exam. Your teacher explains the tasks and dates in class.

During practice, we can try an idea and look at what happens. If the
result is different from what we expected, a hint or an example may help
us choose a next step. You can ask for help at any point.

## Which path can I start with?

Either. In the website path, we learn HTML for a page's structure and CSS
for its appearance. In the data path, we learn to make tables and use
SQL to find information in them.

If you are learning in class, your teacher can help you find where to
begin. If you are learning on your own, you can choose what interests you.

## What if I miss a class or need more time?

You can return to a page and work through an example again. Some ideas
may need another explanation or more practice. Your teacher can help you
choose what to try next.

The search box on the front page can help you find a topic. If you want
to take a break, the saving information below explains how to keep your work.

## Can I use this on a phone?

You can read the tutorials on a phone. Editing website files is usually
more comfortable on a computer, with room for the editor and browser.

## What if my teacher's instructions are different?

The college sets the projects and the exam. Your teacher can explain how
these pages relate to your class and which instructions apply to a task.
You can ask about any difference that is unclear.

## Where is my work saved?

Your website files stay in your GitHub repository when you save them
there. A repository holds a project's files and records changes to them.
Saving a file only on your computer does not send it to GitHub.

On the data pages, **Your table** saves its SQL text in this browser when
you use **Run** or **Load**. Typing alone does not save it. The saved text
loads and runs again on pages with the same **Your table** box.

The saved copy does not move to another browser or device. Clearing
browser data removes it, and browser settings or full storage can prevent
saving. **Download** makes a `.sql` file of the text in the box. You can
keep this file and use **Load** to open it on another computer.

Other SQL boxes do not save changes between visits. You can use their
**Download** button to keep the text. In the older playground linked from
the README, you can copy your SQL into a file before leaving.

The small website editors inside tutorials also start again when you
return. **Download these files** lets you keep your changes.

## What does Reset do in a SQL box?

**Reset** restores the original code and clears that box's database and
result. In **Your table**, it also removes the saved SQL text. **Download**
lets you keep a copy of your current text before using Reset.

## What happens when the course ends?

You can keep using the files in your own GitHub account. SQL work saved
in your browser stays there until it is removed. Downloaded files give
you a copy to keep outside the browser.

## What if something on the site does not work?

[Troubleshooting](tutorial:troubleshooting) has suggestions for problems
such as a blank page or missing styles. You can also ask your teacher.

Most pages have a link at the bottom labelled "Something wrong on this
page? Tell us." It offers options for an error or an explanation that is
wrong or hard to follow. Each option opens a report form on GitHub with
the page and version filled in. Reporting needs a free GitHub account.
You can describe what happened even if you do not know the cause.
