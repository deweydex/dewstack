# FAQ

Here are answers to questions about learning with dewstack.
[Troubleshooting](tutorial:troubleshooting) is the page for when
something does not work.

## Do I need to know how to code before I start?

No. The first tutorials introduce the tools and show examples to try.
Later pages build on those ideas. You can return to an earlier
explanation whenever it helps.

## Do I need an account or anything to install?

You can read the tutorials and try the data exercises in your browser
without an account or anything to install.

The website exercises use a free GitHub account. GitHub keeps your
website files and publishes your site. Its website includes an editor,
so you can work in your browser. If you prefer an editor on your
computer, VS Code is one option.

## Is this graded?

The tutorials and exercises are not graded. Only the two projects and
the exam are, and your teacher covers the dates and the briefs for those
in class. Breaking something and fixing it while you are still learning
costs nothing here.

## Which path should I start with?

Either. In the website path, we learn HTML for a page's structure and
CSS for its appearance. In the data path, we learn to make tables and
use SQL to find information in them.

If you are learning in class, your teacher can help you find where to
begin. If you are working on your own, pick whichever interests you
more.

## What if I miss a class or need more time?

Each page is short and stands mostly on its own. You can return to a
page and work through an example again. Some ideas need another
explanation or more practice.

The search box on the front page can help you find a topic by name.
The saving information below explains how to keep your work if you want
to take a break.

## Can I use this on a phone?

Yes, for reading the tutorials. Editing website files is usually more
comfortable on a computer, with room for the editor and browser side
by side.

## What if my teacher's instructions are different?

The college sets the projects and the exam. Your teacher can explain how
these pages relate to your class and which instructions apply to a task.
Follow your teacher when there is a difference.

## Where is my work saved?

Your website files stay in your GitHub repository when you save them
there. A repository holds a project's files and records changes to them.
Saving a file only on your computer does not send it to GitHub.

On the data pages, **Your table** saves its SQL text in this browser
when you use **Run** or **Load**. Typing alone does not save it. The
saved text loads and runs again on pages with the same **Your table**
box.

The saved copy does not move to another browser or device. Clearing
browser data removes it, and browser settings or full storage can
prevent saving. **Download** makes a `.sql` file of the text in the
box. You can keep this file and use **Load** to open it on another
computer.

Other SQL boxes do not save changes between visits. You can use their
**Download** button to keep the text. In the older playground linked
from the README, copy your SQL into a file before leaving.

The small website editors inside tutorials also start again when you
return. **Download these files** lets you keep your changes.

## What does Reset do in a SQL box?

**Reset** restores the original code and clears that box's database and
result. In **Your table**, it also removes the saved SQL text.
**Download** lets you keep a copy of your current text before you reset.

## What happens when the course ends?

Your GitHub account and its files are yours, not the college's. You can
keep using them after the course. SQL work saved in your browser stays
there until it is removed. Downloaded files give you a copy to keep
outside the browser.

## Something here is actually broken. What do I do?

[Troubleshooting](tutorial:troubleshooting) groups the problems people
meet most often: a blank page, styles that will not apply, GitHub not
taking a push. Each one comes with the checks that usually find it.

Most pages have a link at the bottom, "Something wrong on this page?
Tell us." It offers options for an error or an explanation that is wrong
or hard to follow. Each option opens a report form on GitHub with the
page and version filled in. Reporting needs a free GitHub account. You
can describe what happened even if you do not know the cause.
