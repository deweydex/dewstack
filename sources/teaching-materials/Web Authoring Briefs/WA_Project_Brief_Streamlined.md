## Technical Requirements

### Across All Pages

Your website must include:

**HTML Structure:**
- Semantic HTML5 (header, nav, main, section, footer, etc.)
- Proper document structure with DOCTYPE, head, body
- Appropriate heading hierarchy (h1-h6)
- Multiple paragraphs and sections
- Both ordered and unordered lists
- At least one data table with proper structure
- Multiple images with descriptive alt text
- Internal links connecting your pages
- At least one form (on any page)
- At least one special HTML character entity

**CSS Implementation:**
- External stylesheet only (no inline or internal styles)
- Element, class, and ID selectors
- **CSS Flexbox must be used** (for navigation, cards, or page sections)
- **CSS Grid must be used** (for main layout or content organization)
- Font and text properties demonstrating typography control
- Color scheme with background properties
- Border properties with border-radius where appropriate
- Proper use of padding and margins for spacing
- Link pseudo-classes (a:link, a:hover, a:active, a:visited)
- Consistent navigation across all pages
- Responsive design with media queries

**Design Principles:**
- Contrast: Clear visual hierarchy
- Repetition: Consistent design elements
- Alignment: Clean, organized layout
- Proximity: Related elements grouped together

## How to Approach This Project

### Phase 1: Planning (Start Here)

**Before you write any code:**

1. Open `planning_template.md` 
2. Work through each question - this is your design process
3. Create your site map showing page relationships
4. Sketch or wireframe your layout
5. Choose your color scheme and fonts
6. Plan your navigation structure

**Why planning matters:** Good planning makes coding easier. You'll know what you're building and why, rather than making it up as you go.

### Phase 2: Building

**Start with structure, add details later:**

1. Build your HTML structure first (all pages)
2. Add navigation to all pages
3. Create basic CSS for layout and consistency
4. Add content to each page
5. Refine styling and details
6. Test everything works

**Commit regularly to GitHub** as you work - this shows your development process.

### Phase 3: Testing & Documentation

**After your site is complete:**

1. Validate your HTML and CSS
2. Test in multiple browsers
3. Test on different screen sizes
4. Complete `readme_template.md` to document what you built
5. Complete `maintenance_template.md` with future plans

## Common Questions

**How do I choose page topics?**  
Pick something you're genuinely interested in - you'll be spending time with this content. Could be a hobby, your favorite games/movies, a local business concept, a portfolio of your work, anything that gives you 5+ pages of content to work with.

**Can I use content from Assignment 1?**  
Your topic must be different, but you can reuse techniques you learned. The landing page can be similar in structure to your Assignment 1 page, but the overall site must be new.

**Do all pages need forms/tables?**  
No - the requirements are across all pages. One page might have your form, another might have your table. Distribute elements naturally where they make sense for your content.

**Where should I use Flexbox and Grid?**  
Both are required but you choose where they work best for your design. Common uses: Flexbox for navigation bars, card layouts, or footer layouts (things in rows or columns). Grid for main page layouts, galleries, or content sections (things in both rows AND columns). You can use them multiple places - whatever makes sense for your site.

**How detailed should my planning be?**  
Detailed enough that you could hand it to another developer and they'd understand what you're building and why. If you find yourself writing "I don't know yet," do more planning.

**What if I get stuck?**  
Use the resources available: class notes, MDN Web Docs, W3Schools, your Assignment 1 work. The browser's developer tools help debug CSS and HTML issues. Commit your work frequently so you can revert if needed.

**How do I submit?**  
Push all your files to a public GitHub repository. Submit the repository URL via Moodle. Make sure your repository is public - private repositories can't be accessed for grading.

## Evaluation Notes

**What makes a strong project:**
- Thoughtful planning that shows decision-making
- Clean, well-structured HTML using semantic elements
- Professional CSS that creates visual consistency
- Working navigation that makes sense
- Content that's appropriate for the identified audience
- Documentation that explains your choices
- Evidence of testing and refinement

**What makes a weak project:**
- Random pages with no clear purpose or connection
- Minimal planning or planning done after the fact
- Messy, inconsistent code
- Broken links or navigation
- Generic content with no thought to audience
- Incomplete documentation
- No evidence of testing

**Focus on learning:** This project is about demonstrating web authoring skills and design thinking, not about being a professional web designer. Clean, simple, and well-executed is better than complex and broken.
